## A. 选牌交互（用户原话与四条铁律）

用户反馈：
1. 「点提示系统会智能选牌，但如果我不满意还不能把系统选的牌放下」—— 严重 bug。
2. 「选牌不要做成浮动」：点一张牌，它左右的牌浮起来，中间这张很难选/看不到。
3. 「最好做成鼠标滑动可以连选」。
4. 「当我自己选择的时候也会智能选牌」；「用户自己选的一些牌不符合某些场景时，智能选牌不要出现，而是把选择权交给用户」；「用户也可能不满意智能选牌的其中几张牌」。

### A.1 现状根因（已定位，直接改）

- `Hand.onClick` 把点击交给 `smartPickForCard` 扩成**整手**；跟牌时它取的是 `ranked.find(含该牌)`，
  和当前选中的那一手可能不是同一手，`toggle` 发现"没全选中"就再**加**一堆牌 —— 于是点选中的牌反而越点越多，永远放不下。
- `.sj-hand-card.on` 把 `.sj-hand-card-lift` 抬 14px **并把 z-index 提到 3**。扇子是左压右叠放的，
  左邻一旦抬到上层，就把中间那张唯一露出的左窄条盖掉，用户看到的正是"左右浮起来，中间的看不见"。
- 横扫多选只在 `onPointerEnter` 里 `selectMany`：只能加不能减；按下的第一张永远选不上（pointerup 不在同一元素上 click 不触发）；
  手机上触摸有隐式 pointer capture，`pointerenter` 根本不会来，所以移动端滑选完全不工作。

### A.2 目标行为（验收标准，逐条可测）

**几何铁律**：手牌的 `<button>` 几何、层级（z-index）、transform 在悬浮/选中时**一律不变**。
选中态只用颜色/描边/角标表达；整手牌轮到我时的 6px 整体上浮保留（那是整体、均匀的）。
`.sj-hand-card` 顶部为抬起预留的 padding 一并去掉（只留角标需要的 2–4px）。

**选中态视觉**（每张牌永远露出的是左窄条 + 顶边）：
- 牌面盖一层暖金半透明色（约 `rgba(243,224,176,.22)`），顶边和左边各一条 2–3px 金线（用 `inset box-shadow`，不用 outline，outline 会被右邻盖住）；
- 左上角一枚 ✓ 小圆角标（直径 ≈ 牌宽 22%），落在 rank 索引旁边；
- 选中瞬间给一个 220ms 的金色辉光脉冲（只动 box-shadow/opacity，不动 transform）；`prefers-reduced-motion` 下不脉冲；
- 被动建议（`hinted`）保留，但改成**淡蓝虚线内描边**，和金色选中态一眼可分；选牌一开始就撤掉（现有逻辑）。

**单击 = 只动这一张**：
- 点未选中的牌：加上这一张；点已选中的牌：**只去掉这一张**，绝不联动。
- 唯一例外 —— **被迫补齐**（A.3）：加上这张之后，规则上**所有合法出法都必须**一起带的牌，自动补上；
  规则不强迫的一张也不加。补上的牌同样可以再单独点掉。
- 双击/300ms 内连点同一张 = 用户主动要"整单位"：扩成含这张牌的最长拖拉机 > 对子；这是用户触发的，不算自动。

**按住横扫多选**（桌面鼠标、手机手指都要能用）：
- 事件全部改在行容器（`.sj-hand-row`）上用 pointer 事件处理：`pointerdown` 时 `setPointerCapture`，
  `touch-action: none`，`pointermove` 用 `clientX` 对照缓存的各牌 `getBoundingClientRect()` 判定命中
  （第 i 张的可见区间 = `[left_i, left_{i+1})`，最后一张到 `right`），不用 `pointerenter`。
- 模型是**按 x 的区间框选**：锚点 = 按下的那张 i0，当前 = i1，扫过集合 = 锚点所在行里下标在 `[min,max]` 内的牌。
  **模式由锚点牌按下时的状态决定**：未选中 → 这次拖动是"选"，已选中 → 这次拖动是"取消"。
  每次 move 重算 `预览 = 初始 ∪ 扫过`（选）或 `初始 \ 扫过`（取消），所以往回拖会自动撤销，不会越拖越多。
- `pointerup` 提交；`pointercancel` 回到初始；移动 < 6px 且没离开锚点牌 = 单击（走上面的单击规则）。
- 拖动是用户逐张明确选的，**不做任何补齐**。
- 手机双行手牌：只在锚点所在行内框选。
- 不再用 `onClick`；键盘 Enter/Space 在 button 上等价单击（可达性）。

**提示按钮（`提示`）**：
- 选中为空：和现在一样按 `suggest` 排序循环，文案 `提示 k/n`。
- 选中非空且不完整/不合法：文案改成 **`补齐`**，候选 = `suggest(view, hand, 60)` 里**包含当前所选全部牌**的那些，
  按原顺序循环；一个都没有时用 `complete.ts` 枚举的合法超集（按"不带分、牌小"排序）；仍然没有 → toast
  「这几张凑不成一手，先放下再提示」，**不改动选牌**。
- 选中已是合法一手：`提示` 变为 `换一手`，循环到下一个候选（替换）。
- 无论哪种情况，提示之后每一张都还是可以单独点掉。

**唯一解自动预选**：保留"轮到我且整手被迫（只有一种合法出法）时预选"，但要改用 A.3 的 `forcedCompletion(空集)`
判定，且**只有整手都被迫才预选**；部分被迫不预选。用户点掉之后不能被选回来（现有 turnKey 依赖保留）。

### A.3 `shared/sj/complete.ts`（纯函数，可测）

```ts
/** 包含 must 的全部合法跟牌（must ⊆ hand）。只在 lead 存在时有意义；首出返回 []。 */
export function legalFollowsContaining(hand, must: SjCard[], lead: SjShape, ctx, cap = 4000): SjCard[][]
/**
 * 被迫补齐：所有包含 must 的合法出法的**交集**，减去 must 本身。
 * 没有任何合法超集 → null；交集不比 must 多 → []。
 * 首出（lead 为 null）永远返回 []：单张总是合法的，规则从不强迫。
 * 枚举超过 cap 次校验就放弃（返回 []）：宁可不补，不可卡顿。
 */
export function forcedCompletion(hand, must, lead | null, ctx): SjCard[] | null
```

必须覆盖的情形（写成测试）：
- 首出对子，我该门只有一个对子（其余是单张）：点对子中的一张 → 另一张被补上；点单张 → 只加单张（出牌按钮下方照常显示原因）。
- 首出对子，我该门有两个对子（KK、77）：点 K → **补上另一张 K**（含这张 K 的合法出法只有 KK，规则强迫）；
  点 K 再点 7 → 7 只加进去、不补（此时无合法超集，按钮灰并显示原因）。
  （2026-09-03 裁定：以"含 must 的全部合法出法的交集"为唯一定义，旧例子写反了。）
- 首出 3 张甩牌/拖拉机，我该门只剩 2 张：点其中一张 → 另一张该门牌被补上，第三张不补（垫哪张是用户的事）。
- 首出单张，我该门无牌：点任意牌 → 不补。
- 首出二连对，我有三连对 AAKKQQ：点 K → **只补另一张 K**（AAKK 与 KKQQ 的交集）；点 A → **补齐 AAKK**（含 A 的合法出法只有它）。
  同一裁定：交集定义优先，拆法不唯一时交集自然变小，而不是"一概不补"。
- cap 生效：构造一手 20 张同门、首出 8 张甩牌，函数在 cap 内返回 `[]` 且耗时 < 50ms。
- `smartPickForCard` 删除，测试同步改写。

## B. 机器人大脑：从"会打"到"像真人"

用户原话：「机器人的智能程度太差了，完全不像真人打牌。所以智能相关的方面非常重要。」
`suggest` 与机器人同源，所以机器人蠢 = 提示也蠢。这是**头等功能**，不是打磨。

### B.0 总纲（用户追加，优先于 B.2 的逐条清单）

- **分数是唯一的账本。** 每个决策都是对 200 分的期望计算：场外还有多少分牌、桌上有多少分、我方/对方还差多少、
  谁最可能收这一圈、最后一圈值多少。排序基于显式的分值期望函数，不用硬编码的分档顺序。
- **每一圈动态重算。** 只依赖当前公开状态，没有固定开局套路。
- **不能看牌，但有记牌器。** 信息集 = 自己手牌 + 公开已出牌推出的：每门剩几张、剩几张主、剩多少分、已知缺门，
  并据此推测对家与对手的持牌。
- **抠底倍数（用户给定）**：单张 ×2、对子 ×4、两连对 ×8、以此类推 = `2^(1 + 最长拖拉机对数)`，上限 64。
  现有 `digMultiplierForLead` 用的是 `2^(拖拉机张数)`（两连对 ×16），**要改**；rules.ts 的这一处和对应测试划给 B 线程。

### B.1 不可违背

- **不许偷看**：只能用自己的手牌 + 公开信息（`playedIds`、`trick`、`lastTrick`、`voidGroups`、`dealerSeat`、
  `kouSeat`、`trump`、`levels`、`trickNo`、`defenderPoints`、`handTrickPoints`、`penaltyPoints`、`flipped`）。
  `bottom` 只有 `me.seat === kouSeat` 时可读（那 8 张是他自己扣的）。
  写一个「防偷看」测试：把其他三家手牌随机互换/重洗，`botPlay` 输出必须完全一致。
- 确定性保留：同 rng 种子可复现。`suggest` 签名不变。
- 输出永远合法（保留现有兜底）。

### B.2 要具备的"人类常识"（每条一个可执行的场景测试）

先建一个 `Brain` 视图（纯函数）把公开信息算成人看牌桌时脑子里的那几件事：
我是庄家方还是闲家方；闲家还差多少分（`80 - defenderPoints` 之类，按变体）；还剩几圈；
每门未露面的牌（`unseenCards`）；场外还有多少主（未露面主牌数）；哪家已知缺哪门；
对家/对手在本圈是否**稳赢**（`secureWin`：剩余要出的对手里，没人能用同门更大的牌盖过，
且不存在"缺门 + 场外还有主 + 未知缺主"的毙牌可能）。

**首出**
1. 绝张先收（现有），但**尾局留底**：若我手里有一手主牌绝张（对子/拖拉机更好，`digMultiplier` 翻倍）
   足以锁定最后一圈，且还有别的安全出法，就把它留到最后一圈再出 —— 抠底是升级最大的一笔账。
2. 抽主要看账：庄家方持主多于场外估计（`我的主 > 场外主 / 3` 之类）且底有分（庄家知道）时坚决抽主；
   两个对手都已知缺主就**停止抽主**；抽主时若我持有顶张主就先用大的把对手的主砸出来，否则用小对子。
3. 对家已知缺门、对手未缺门 → 主动打**这门的分牌**（10/K）让对家毙上来（现有只给了加权，改成明确的"喂分"档）。
4. 对手已知缺门且场外还有主 → 这门只出小牌或不出（现有）。
5. 长门小牌探路（现有）；探路优先选**我手里握有该门大牌**的门，一轮之后能建立绝张。
6. 尾局（剩 ≤ 5 圈）先数牌：每门场外剩几张、谁缺门，能收的全收，不能收的把分留给对家。

**跟牌**
7. **对家稳赢就垫分**，无论我在第几位（现在只有末家才给）；对家不稳则不垫，垫最小不带分。
8. 「二家小，三家大」：我是第二家、桌上没分、对家还没出 → 不花大牌，除非我这张是绝张。
9. 对手领先且值得抢 → 最小能赢（现有）。对手已经毙了 → 只在桌上分值得时**用最小能盖过的主**再毙。
10. 缺门时：桌上有分或对家不稳 → 用**最小能毙**的主；对家稳赢 → **绝不盖自家**，垫分。
11. 垫牌造缺门：压不过时优先从**最短的副牌门**垫（下一次这门就能毙），不拆对子、不垫分、不动主（把现有 `discardWeight` 加"门长"项）。
12. 甩牌跟牌：候选从 3 手 compose 扩到结构化枚举（必出拖拉机/对子的低/高各取 + 填充低/高/带分），≥ 8 个候选后按同一把尺子排序。
13. 庄家方防分：对手要赢的圈绝不带分进去（现有），并且**留住能截分的主**到有分的圈。

**亮主 / 抄底 / 扣底**
14. 扣底除了造缺门，还要**保证底里没有分**（庄家方最怕被抠），实在扣不掉分时扣 5 不扣 10/K；持主多时可留一门长副牌不扣。

**像真人的节奏**
15. 找到机器人出牌延时的实现（`BotMove.delay`）：改成按决策难度变化 —— 只有一种合法出法 500–900ms，
    多候选 1.2–2.2s，尾局/抠底相关再 +0.5s，带 rng 抖动；确定性由 rng 保证。
