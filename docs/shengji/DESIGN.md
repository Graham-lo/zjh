> 本文是升级功能的**唯一权威规范**。实现、测试、验收都以此为准；实现中发现规范有歧义或矛盾，
> 先在本文修订再改代码，不要在代码里"顺手"另立规则。
>
> 产品决定（用户已定，不再讨论）：
> 1. **两副牌**（108 张），**四人两队，对家为一队**，不做一副牌模式。
> 2. 两个变体，各自是独立的房间类型，在首页选择：**「五十K」**（级牌只有 5 → 10 → K）与
>    **「打通关」**（2 → 3 → … → K → A）。用户原话"从 1 打到 K"按标准 2→A 阶梯理解；阶梯是一个配置数组，改起来是一行的事。
> 3. **炸金花不动**：首页改成选游戏，炸金花的牌桌、规则、流程一律不改。
> 4. 质量标准是"顶格"：规则细节、交互、动效、声音都按 `client/styles.css` 顶部注释和 README 里
>    炸金花已经达到的水准来，而不是"先能玩"。

## 1. 规则规范（两副牌升级 / 拖拉机）

### 1.1 牌

- 两副标准扑克含大小王，共 108 张。每张牌有唯一 `id`（如 `S5a` / `S5b`、`JB a`），客户端按 id 选牌。
- 花色 `S H C D`，点数 2–14（J=11 Q=12 K=13 A=14）；小王 `{suit:'J', rank:15}`，大王 `{suit:'J', rank:16}`。
- **分牌**：5 = 5 分，10 = 10 分，K = 10 分。全场 200 分。

### 1.2 级牌、主牌、副牌

- 每队有自己的**级别**（level）。**庄家所在队的级别 = 本局级牌**。
- 有主花色 T 时，主牌从大到小：**大王 > 小王 > 主级牌（T 花色的级牌）> 副级牌（其他三色的级牌，三者相等）> T 花色 A > K > … > 2**（跳过级牌点数）。
- **无主**（NT）时主牌只有：**大王 > 小王 > 级牌（四色相等）**。
- 副牌：每门花色 A > K > … > 2，跳过级牌点数。
- 花色组（suit group）：`T`（主牌，含王和所有级牌）或 `S/H/C/D` 副牌。一张牌只属于一个组。

### 1.3 座位与队伍

- 座位 0–3 顺时针；**0 与 2 一队，1 与 3 一队**。大厅里可以点空座换座，方便朋友组队。
- 4 个座位必须坐满（真人或电脑）才能开局；房主可加电脑补位。
- 每队的级别在整场比赛中保留；房间新建时两队都在阶梯第一级（五十K 是 5，打通关是 2）。

### 1.4 一局的阶段

`lobby → dealing → declaring → kou → chao → playing → hand_end → (下一局 dealing | match_end)`

其中 `chao`（抄底）与 `kou` 之间会来回：有人抄成底就回到 `kou` 由**抄底者**重新扣，扣完再回 `chao` 接着问。

**dealing（发牌）**
- 服务端一次性发好：从庄家（首局从房主）开始顺时针，每人 25 张，剩 8 张为底牌。
- 状态里带 `dealStartedAt`；客户端按 45ms/张 播发牌动画（共约 4.5s）。**亮主从发牌第一张起就开放**，
  服务端不限制"这张牌动画里发到没有"；客户端只在该牌已经飞到手里后才显示亮主按钮。
- 动画播完进入 declaring。

**declaring（亮主窗口）**
- 时长：发牌结束时**已经有人亮了**就再给 3s（留个反主的余地），**一个人都没亮**则给 8s；
  每出现一次新的有效亮主/反主再延长 2s；四人都点了「不亮」立即结束。
  8s 这一档不是排场：没人亮的结局是**默认无主**，也就是说它是本局最后一次抢庄的机会，
  短了等于替所有人决定不亮（常量 `SJ_DECLARE_MS` / `SJ_DECLARE_QUIET_MS`）。
- **反主级别是 7 档**（`trump.strength`），必须**严格更强**才能反主。对级牌的花色大小
  从小到大是 **方块 < 梅花 < 红桃 < 黑桃 < 对小王 < 对大王**：

  | strength | 亮法 | 定下来的主 |
  | --- | --- | --- |
  | 0 | 无人亮主（默认无主） | 无主 |
  | 1 | 单张级牌（**任意花色，彼此相等**） | 该花色 |
  | 2 | 一对方块级牌 | ♦ |
  | 3 | 一对梅花级牌 | ♣ |
  | 4 | 一对红桃级牌 | ♥ |
  | 5 | 一对黑桃级牌 | ♠ |
  | 6 | 一对小王 | 无主 |
  | 7 | 一对大王 | 无主 |

- **单张之间不分花色**：QQ 的「抢亮」是先亮者得，官方只对「对子」列了花色序，
  所以 ♠5 单张**反不掉** ♦5 单张。要改成单张也分花色，只需改 `declStrength` 一处。
- **加固**：当前亮主者可用**同花色**的第二张级牌，把单张（1）抬到**该花色的对子档**（♦→2 … ♠→5）。
  所以加固方块只挡得住单张，梅花/红桃/黑桃的对子照样反得掉 —— **这是规则本身，不是 bug**。
- 同一个人不能用**别的花色**反自己；可以用对王把自己的亮主反成无主。
- 亮出的牌**明牌放在该玩家座位前**直到抄底问完（仍在其手中，可正常打出）。
  扣底时如果把自己亮出来的那张一起扣了下去，它就从明牌里摘掉 —— 那几个 id 是公开的，
  留着等于把底牌里的一张告诉全场。
- 窗口结束时无人亮主：本局**默认无主**（`trump.suit = 'NT'`、`declarerId = null`、`strength = 0`）。
  **不翻底牌** —— 底牌整副原封不动交给庄家扣。既然没人亮过主，也就没有「比现在更强」这回事，
  这一局的**抄底阶段整个跳过**：扣完底直接开打（见 1.4b）。
- **首局庄家 = 窗口结束时亮主有效的那个人**；无人亮主则房主坐庄。后续局庄家按 1.8 轮转，亮主只决定主花色。
- 级别表与判定集中在 `shared/sj/rules.ts`：`SJ_DECL_TIER` / `declStrength` / `checkOverride` /
  `declarationOptions` / `legalDeclarations`。服务端的 `doDeclare`、`doChao`，机器人，
  客户端的亮主条/抄底条**读的都是这一份**，绝不各写各的。

**kou（扣底）**
- 拿到 8 张底牌的人（`kouSeat`：庄家，或者刚抄成底的人；只有他能看到）从 33 张里扣回 8 张
  （任意牌，含分牌和主牌都行）。
- 时限 45s；超时由机器人策略代扣。
- 扣完进入 **chao**，不是直接开打。

**chao（抄底）**

见 1.4b。

### 1.4b 抄底

> 出处：QQ《升级》/《欢乐升级》与炒地皮系规则 ——「待庄家扣底牌之后，要按出牌顺序依次
> 询问其他玩家是否抄底牌。抄底牌的玩家需按照『反主级别』的大小顺序亮出比当前级别高的牌，
> 可以拿起底牌进行重新扣底，并且视同『反主』。抄底牌不限次数。」

- **抄底常开**，没有开关，也没有兼容旧规则的退路。
- **询问顺序**：庄家扣完底 → 从**庄家下家**起顺时针依次问，**跳过庄家**（他刚拿过一次底牌），
  一轮固定是 3 个人。每人 `chaoSeconds`（默认 12s）；超时 / 掉线 / 机器人不想抄一律算「不抄」。
- 被问到的人两个选择：
  - **抄底**：亮出一手比当前 `trump.strength` **严格更高**的牌（形式与 1.4 的亮主完全相同）；
  - **不抄**。
- **不能自反**：轮到当前 `trump.declarerId` 本人时，只有「用对王反成无主」这一种合法。
  加固在这里没有意义 —— 那等于把自己刚扣下去的底牌再拿一次。
  别人反主/抄底之后他就不再是亮主者，下一轮又可以抄了。
- **抄成之后**：
  1. 亮出的牌**明牌**摆到他座位前，旧亮主者的明牌收回；
  2. `trump` 更新为 `{ suit, strength, declarerId: 抄底者 }`，**视同反主**；
  3. 他把 8 张底牌收进手里（33 张），`phase = 'kou'`、`kouSeat = 他`，重新扣 8 张；
  4. 扣完**回到 chao**，从他的下家继续**本轮**，`chaoDirty = true`。
- **一轮问完**（问回起点 = 庄家下家）：`chaoDirty` 为真就清掉它再开一轮，为假则进 playing。
  每抄成一次 `strength` 都严格变大且上限是 7，所以一定收敛，不会一直问下去。
- **庄家归属**：
  - 第 1 局：庄家 = 亮主有效的那个人（1.4），抄底视同反主，所以**首局抄底者坐庄**
    （此刻两队级别相同，换庄不改变本局级牌）；
  - 第 2 局起：庄家按 1.8 轮转，**抄底只改主花色与底牌归属，不换庄**。
  - `enterPlaying` 的首出始终是 `dealerSeat`。
- **无人亮主的局没有 chao 阶段**：`trump.declarerId === null` 时扣完底直接 `enterPlaying`，
  抄底条不显示，`chao` 指令一律报「现在不是抄底阶段」。于是 0 档只会出现在一个**问都不问**的局里，
  抄底的起点永远是某个真实的亮主（≥ 1 档）。
  （`flipped` 字段还留在状态里，但新流程下恒为 `null`，只为读旧存档兜底。）
- **底牌可见性**：只在 `phase === 'kou'` 且 `viewer.seat === kouSeat` 时给他一个人；
  **`chao` 阶段谁都看不到**（它是扣着的，看得到就等于照着底牌决定抄不抄）。

**playing（出牌）**
- 每人每步时限 `turnSeconds`（默认 30s，房主可调 10–180）；超时由机器人策略代出一手**合法**牌。**没有弃牌概念。**
- **四家手牌出完即进入 hand_end。**每人 25 张，但一圈消耗的张数取决于首出的牌型（单张 1 张、对子 2 张、拖拉机更多），所以一局的**圈数是 1–25 之间的变量，不是固定 25 圈**；恒成立的是「每一圈四家出牌张数相同」「一局四家各出满 25 张」。
  （初稿写的"25 轮"是把 25 张牌误当成 25 圈，按中国升级竞赛规则修正。）

### 1.5 牌型（首出）

同一花色组内：
- **单张**
- **对子**：两张完全相同的牌（同花色同点数，来自两副）。
- **拖拉机**：≥2 个**点数相邻**的对子，同一花色组。相邻按 1.2 的顺序判定（跳过级牌点数，所以打 10 时 9 与 J 相邻）。
  主牌里 `T 花色 A → 副级牌 → 主级牌 → 小王 → 大王` 也相邻（对 A + 对副级 = 拖拉机；对主级 + 对小王 = 拖拉机）。
  三张不同花色的副级牌互相**相等**，不相邻，不能连成拖拉机。无主时 `级牌（同花色对）→ 小王 → 大王` 相邻。
- **甩牌**：同一花色组内多个单位（单张/对子/拖拉机）一起出。**合法条件**：其他三家没有能**严格大过**其中任一单位的同类牌型
  （同大的牌仍是先出者大；单张、对子、n 连对分别比较，连对比较最高对）。服务端拿全部手牌判定。
  **甩牌失败**按 QQ/传统网络升级的“被管上牌型强制出小”：先找确实能被管上的牌型；多种牌型都被管时按
  **拖拉机 > 对子 > 单张**取较大牌型，再在该牌型里强制出最小的一组，其余退回手中，并**罚 10 分**：
  闲家失败 → 闲家 −10；庄家阵营失败 → 闲家 +10。客户端无法预判甩牌合法性，出牌后由服务端裁决并回一个 `sj_throw_fail` 事件。

### 1.6 跟牌

设首出在花色组 G，结构为 `(拖拉机长度列表 tr, 对子数 p, 单张数 s)`，总张数 n。跟牌者必须出 n 张，规则按优先级：

1. **有 G 必跟 G**：手里 G 的张数 ≥ n 时必须全出 G；不足时 G 全出、其余任意。
2. 出 G 时**结构尽量匹配**：
   a. 首出含拖拉机：按长度从长到短，每个拖拉机若手里有 G 的同长度（或更长拆出）拖拉机，必须出一个；
   b. 剩余的对子槽位（含未能配上的拖拉机拆成的对子槽位）若手里还有 G 的对子，必须用对子填；
   c. 剩余槽位用任意 G 单张填。
3. 没有 G：任意垫牌，或全出主牌**毙**。

合法性由 `shared/sj/rules.ts` 的 `validateFollow(hand, lead, play)` 判定，服务端与客户端共用一份；客户端只用自己的手牌即可完整判定跟牌合法性（甩牌合法性除外）。

### 1.7 定圈（谁赢这一轮）

- 一手牌能"参与比大小"当且仅当：**全部来自 G 且结构覆盖首出要求**，或（G 不是主时）**全部是主牌且结构覆盖首出要求**。
  覆盖的含义是拖拉机/对子数量不得少于首出，而不是机械地要求结构完全相等；因此副牌散牌可以被“主牌对子带单”或主拖拉机毙。其他跟法只是垫牌。
- 主牌毙 > G 内跟牌。多家盖毙先比**最高优先单位**（最长拖拉机 > 对子 > 单张），同类再比该单位的最高牌。
- 相等（三色副级牌、两副同牌）：**先出者赢**。
- 这一轮的分牌归赢家一队；只累计**闲家**得分 `defenderPoints`。

### 1.8 抠底与结算

- 最后一圈（手牌出完的那一圈）由闲家赢：按**首出最大牌型**计算底牌番数 —— 单张 ×2、对子 ×4、两连对拖拉机 ×8、
  三连对 ×16，以此类推，即 `2^(1 + 最长拖拉机的对数)`，上限 ×64。纯散牌甩仍为单抠 ×2。
  盖毙不会把首出的单抠变成双抠。计入闲家得分。
- 闲家得分 s（含抠底与罚分）→ 结果：

| s | 结果 |
| --- | --- |
| s < 0 | 庄家升 4 级 |
| s = 0 | 庄家升 3 级（**大光**） |
| 5 ≤ s < 40 | 庄家升 2 级（**小光**） |
| 40 ≤ s < 80 | 庄家升 1 级 |
| 80 ≤ s < 120 | 闲家上台，不升级 |
| 120 ≤ s < 160 | 闲家上台，升 1 级 |
| 160 ≤ s < 200 | 闲家上台，升 2 级 |
| s ≥ 200 | 闲家上台，升 3 级 |

- **庄家轮转**：庄家守住（s < 80）→ **庄家的对家**坐庄；被打下（s ≥ 80）→ **庄家的下家**（顺时针下一位，必是闲家）坐庄。
- **升级夹到阶梯顶**：不能越过顶级（五十K 是 K，打通关是 A）。
- **通关**：**处于顶级的队作为庄家守住一局**即赢下整场比赛 → `match_end`。顶级的队被打下则留在顶级、丢庄。
- hand_end 展示 9s（抠底翻牌 + 计分 + 升级动画都要看完），然后自动发下一局（房主可提前点「下一局」）。
- match_end：展示通关庆祝；「再来一场」把两队级别重置到阶梯首级，庄家重新由亮主决定。

### 1.9 断线、超时、退出

- 断线保留座位；轮到掉线者由机器人策略代打（不等待）。回来即接管。
- 局中有人「离开」：座位由电脑接管到本场结束；大厅里离开则空出座位。
- 房主掉线 20s 移交（沿用炸金花逻辑）。
- 某家跟牌时实际垫出别组牌，公开记为该门**缺门**；四个客户端与电脑玩家共享同一份公开记牌，绝不从服务端暗牌偷推。

### 1.10 机器人（也是超时代打与「提示」的来源）

设计细节见 `docs/shengji/BRAIN-DESIGN.md`，这里只记结构与实测数字。
`shared/sj/bot.ts` 保持纯函数、确定性（可注入随机源），内部拆成 `shared/sj/brain/*`：

| 文件 | 职责 |
|---|---|
| `view.ts` | **记牌器**：由公开信息建 `BrainView`（每门的场外张数/分数/绝张、剩余主、已证明的缺门与"无对"、持牌概率、分数账本） |
| `infer.ts` | 持牌推断：`pBeat` / `pTrump` / `secureWin` / `pTeamWin` |
| `value.ts` | 边际价值 `m`、各项代价（trumpSpend / winnerSpend / structureBreak / voidGain / giftRisk / probeValue / tempo） |
| `candidates.ts` | 合法候选枚举（首出 / 跟牌 / 甩牌），每个候选带 `why` |
| `evaluate.ts` | **唯一的 EV 函数**，首出、跟牌、甩牌、最后一圈全走它 |
| `declare.ts` | 亮主 / 反主 / 加固 / 抄底 / 钓鱼亮主，含发牌途中的逐张决策 |
| `kou.ts` | 扣底打分 + closer 识别 + 抠底计划 `digPlan` |
| `lead.ts` / `follow.ts` | 首出 / 跟牌的排序，外加抽主价值与尾局的一步展望 |

一切排序都出自同一条式子（没有任何写死的牌型档次）：

```
EV = sign × [ (2·pTeamWin − 1)·trickPts + pTeamWin·tempo
              − trumpSpend − winnerSpend − structureBreak
              + voidGain + probeValue − giftRisk − throwRisk + digPlan ] × m
```

`sign` 是"我是闲家方还是庄家方"，`m` 是这一分现在值多少：
`m = 1 + 2·exp(−(d/12)²)`，d 是预计终局分 `sProj` 到门槛（0/5/40/80/120/160/200）的距离，
**已经越过的门槛按 1.6 倍距离折算**（分只增不减，没拿到的门槛才是目标），
通关局的 80 那道再 ×1.5。所以「过 80 之后目标反转」「通关局更保守」「空分局拼大光」
都是算出来的，代码里没有一句 `if (defenderPoints > 80)`。

抠底倍数按**首出牌型**：`2^(1 + 最长拖拉机的对数)`，上限 ×64（见 1.8）。
`digPlan` 把"手里那个主牌绝张单位（closer）"折成分：提前动它是负，最后一圈用它首出是正 ——
"尾局留大主"因此也是算出来的。

节奏（BotMove.delay）：出牌 `botThinkMs` 唯一合法解 500–900ms、多候选 900–1500ms、
前两名接近 1500–2400ms，最后一圈或动到 closer 再 +500ms，上限恒 < `turnSeconds/2`；
表态（亮主/抄底）600–1500ms；扣底 3–6s；**发牌途中的亮主**排在"那张牌到手 + 200–600ms 反应"。

硬约束（都有测试）：只读自己手牌 + 公开信息（底牌仅扣底者可读），把其余三家重洗后
四类决策逐字节不变；同种子可复现；输出恒合法（跟不出就退回 `composeFollow`）。

实测（`node scripts/sj-bench.mjs 300 200`，v1 旧脑子快照在 `tests/fixtures/bot-v1.ts`）：

- 自对弈 300 局：闲家平均 79.5/200、上台率 52.7%、抠底 145 次（平均 ×2.37）、甩牌失败 11 次（3.7%，都是算过账的赌）
- A/B 对 v1：新脑子坐 0/2 胜率 **63.5%**，坐 1/3 **64.0%**（两个方向都 ≥60%）
- 决策耗时：n=26796，p50 0.036ms、**p99 0.477ms**、max 2.934ms（要求 p99 < 20ms）

「提示按钮」复用同一个 `suggest(view, hand)`，看到的信息和机器人完全一样。
「帮我扣」同理：`KouDi` 把整个 `SjPublicRoom` 递给 `botKou`（入参类型 `SjBrainState`，
`SjRoomState` 和 `SjPublicRoom` 都满足，有编译期护栏钉着），所以真人拿到的建议和电脑代扣**逐字节相同** ——
针对上一个亮主者造缺门（§9.B6）和闲家抄成底后埋 K/10 等抠底（§9.C6）对真人一样生效。
记牌器读的每一项都是公开信息，别人的 `hand` 在公开视图里是空数组，大脑本来就不碰它。

### 2.4 SjRoomState（要点）

```ts
interface SjRoomState {
  kind: 'sj_510k' | 'sj_2a'; id; code; hostId; createdAt; log; actionSeq;
  settings: { turnSeconds: number; kouSeconds: number; chaoSeconds: number; autoContinue: boolean };
  players: SjPlayer[];           // seat 0-3；team = seat % 2；hand: SjCard[]（服务端）
  phase: 'lobby'|'dealing'|'declaring'|'kou'|'chao'|'playing'|'hand_end'|'match_end';
  levels: [number, number];      // 两队级别（阶梯里的点数）
  handNo; dealerSeat;            // 庄家座位
  trump: { suit: Suit|'NT'|null; level: number; declarerId: string|null; strength: number; cardIds: string[] };
                                 // strength 是 1.4 的 7 档表；老快照在 migrate() 里换算一次
  passed: string[];              // 本局点过「不亮」的人
  dealStartedAt; declareEndsAt; turnDeadline;
  kouSeat: number;               // 当前该扣底的人：庄家，或刚抄成底的人（1.4b）
  chaoSeat: number | null;       // 抄底询问里当前被问到的座位
  chaoDirty: boolean;            // 这一轮询问里有人抄成过 → 问完还要再开一轮
  bottom: SjCard[];              // 底牌（服务端；扣底后是 kouSeat 那个人扣下的 8 张）
  bottomRevealed: boolean;       // 抠底/局末公开
  trickNo; leaderSeat; turnSeat;
  trick: { seat: number; cardIds: string[] }[];   // 当前圈已出
  lastTrick: {...} | null;       // 上一圈，给「看上一轮」
  defenderPoints: number;        // 闲家得分（含罚分）
  capturedPointCards: SjCard[];  // 闲家赢到的分牌（展示分牌堆）
  voidGroups: SjGroup[][];       // 每个座位公开确认的缺门；新局清空
  result?: { defenderPoints; dig?: {base; multiplier; total}; outcome; nextDealerSeat; levelsAfter }
  matchWinner?: 0|1;
}
```

`sanitize(state, viewerId)`：只给自己的 `hand`；别人只给 `handCount`；底牌只在 `kou` 阶段给
`kouSeat` 那一个人、`bottomRevealed` 后给所有人（**`chao` 阶段谁都看不到**）；
亮主/抄底的明牌、当前圈、上一圈、分牌堆公开。**任何测试都要断言别人的手牌不会出现在响应里。**

### 2.5 Hub 定时器

| 阶段 | 定时 | 到点动作 |
| --- | --- | --- |
| dealing | dealStartedAt + `SJ_DEAL_MS`（25×400ms + 600 = 10.6s） | → declaring，declareEndsAt = now + 3s（已有人亮）或 8s（无人亮） |
| declaring | declareEndsAt（每次有效亮主 +2s） | 无人亮 → 默认无主；→ kou |
| kou | kouSeconds | 机器人代扣（代的是 `kouSeat`，不一定是庄家）|
| chao | chaoSeconds（默认 12s，每人一次） | 自动「不抄」；有人抄成 → 回 kou 重扣，扣完接着问 |
| playing | turnSeconds；机器人 500–1100ms 思考 | 机器人策略代出 |
| hand_end | 9s | 下一局（autoContinue）或等房主 |

服务端每次状态变更仍是 `broadcast(room, events)` + 防抖快照；账户统计在 hand_end/match_end 写回。

### 2.6 兼容

- 老快照没有 `kind` → `'zjh'`。
- 老客户端不认识 `sj_*` 事件 → 忽略（switch default）。
- `/healthz` 加按 kind 的房间计数。

## 3. 客户端设计

### 3.1 首页（重设计）

结构从"一个游戏 + 入座卡"变成 **「选桌 → 入座」**：

- 左侧品牌区保留 `午夜牌会` 的气质（墨绿近黑 + 香槟金、大花色水印、发丝金线），标题改为 **「牌 会」**（eyebrow：私人牌会 · FRIENDS ONLY），lead 改成一句涵盖两种游戏的话。
- 中间是**三张"桌卡"**（Game cards），横排（≥1200px）/ 纵排（手机）：
  1. **炸金花** —— 2–6 人 · 豹子 顺金 金花 阶梯丝带 · 三张悬浮牌（沿用现有 hero）。
  2. **升级 · 五十K** —— 4 人 · 两副牌 · 阶梯 `5 → 10 → K` 三枚级牌徽章。
  3. **升级 · 打通关** —— 4 人 · 两副牌 · 阶梯 `2 … A` 十三格细丝带，当前高亮 2。
  每张桌卡：顶部游戏名（衬线金渐变）、一行规则 tagline、人数/副数小标、底部 **「开一桌」** 主按钮。
  选中态：卡片抬起 + 金边 + 桌面绒布色泛起（炸金花墨绿、升级用**深蓝墨**）。
- 右侧入座卡不变（头像、昵称、房号六格、加入）。**加入房间不需要选游戏**，房号决定一切；受邀链接直接进入。
- 桌卡 hover/选中的绒布色，就是进入后牌桌的底色 —— 从首页到牌桌的颜色连续。

### 3.2 升级牌桌：视觉语言

- 和炸金花同一套 token（金三层、玻璃面板、发丝线、字体栈），但绒布换成**深蓝墨**（`--sj-felt: #14294a / --sj-felt-2: #0c1a33`），
  一眼能分辨"这是另一间房"。**主花色定下后，桌面顶灯的光池色随主花色变**：♠ 冷石墨、♥ 绛红、♣ 森绿、♦ 琥珀、无主 紫罗兰。这是整桌最强的记忆点。
- 牌沿用 `PlayingCard`（正反面、3D 翻面），新增 `size="hand"`（手牌扇）和王牌面（大王金冠、小王银冠，Joker 竖排文字）。

### 3.3 布局

**桌面（≥1200px）**：三栏。左栏 **记分板**（两队级别徽章、庄家标记、主花色大徽章、闲家得分环 0→80→200、分牌堆缩略、底牌 8 张牌背、圈数与已出张数「第 n 圈 · 已出 m/25 张」）；中栏牌桌；右栏 牌桌记录（沿用 Dock 常驻）。
牌桌：对家在上、左右为对手、我在下。每个座位前有一个**出牌区**，当前圈四手牌各落在各自座位前。
我的手牌：**底部扇形**（25 张，自动排序：主牌在左 → 副牌按 ♠♥♣♦），可横向缩放，卡片间距随宽度自适应；选中**不抬牌**（见 3.4），只加金色蒙版与 ✓。
操作条在手牌上方：`提示` `出牌`（只在选牌合法时点亮）`看上一轮`。
**手机（≤780px）**：记分板压缩成顶栏一行（级别 · 主 · 闲家分/80）+ 可展开；手牌两行扇形或横向滚动（≥ 25 张在 390px 上不能一行），选牌同样只变色不抬起；出牌按钮固定底部。

**大屏**：沿用 `--card-*`/`--seat-*` 变量放大策略；≥1880px 手牌卡 `--card-hand-w` 92px。

### 3.4 交互细节（必须做到）

- 选牌：**单击一张只动这一张**（选中、或者取消选中）。唯一的例外是「被迫补齐」——
  只有当规则根本不允许这张牌单独出现时，才把躲不开的那几张一起选上。判据定死在
  `shared/sj/complete.ts`：**所有包含已选牌的合法出法的交集，减去已选牌本身**；
  交集里的每一张都满足"只要这手带着它，就一定也带着这张"，所以"规则不强迫的一张也不加"
  是定义的推论，而不是另贴的启发式（枚举带 4000 次校验的 cap，宁可不补也不卡顿）。
  系统补上的牌**照样能一张张单击放下** —— 取消永远是纯粹的取消，不触发任何补齐。
- 双击（或 300ms 内连点同一张）：选中包含它的**最长拖拉机 > 对子 > 这一张**，再双击整组取消。
  这是"少点几下"的便利，和跟牌规则无关。
- 按住横扫：在手牌上按下并横向拖动，**框选扫过的那一段**。选还是消由**按下那一张**的
  状态决定 —— 按在没选中的牌上是选，按在已选中的牌上是取消，往回拖会实时撤销，
  不会越拖越多。手机同样可用（指针事件挂在行容器上按 x 区间命中，不依赖 `pointerenter`）。
- 选中态**绝不移动牌、绝不改层级**：手牌扇是左压右叠的，一张牌只露出左边一条窄边，
  把它抬起来或提 z-index 就等于让左邻盖住它唯一露出来的那条。所以选中只用颜色表达 ——
  暖金蒙版 + 顶/左两条金线 + 左上角一枚 ✓，几何和 transform 一概不动。
- 「绝不移动牌」是**整块底部区域**的约束，不只是那张牌自己。手机（≤780px）上手牌折成两行、
  紧贴出牌条，出牌条只要长高一点，整排手牌就跟着上下跳，横扫到一半牌会从手指底下溜走。
  所以两条硬性规矩：
  - 出牌条下方那行说明**永远占位**（`.sj-why-slot` 带 `min-height`，`.sj-why` 的 `line-height`
    跟它写成同一个数），并且**最多显示一条** —— 优先级是 不合法的原因 > 打法提醒 > 唯一出法。
  - 手牌上的状态类名一律带 `sj-` 前缀（`sj-hint` / `sj-blame`）。全局 `styles.css` 里有个
    `.hint { margin: 12px 0 0 }` 的段落助手，裸用 `hint` 会把被提示的那张牌整个往下压 12px，
    提示一出现整行就错位。
- 自动预选：轮到我、而**规则本身**只允许一种出法时（`forcedCompletion(hand, [], lead)` 补出的
  张数正好等于该跟的张数），直接把那一手选好。只自动选，绝不自动出牌；玩家取消掉之后
  不会又被选回来。
- 提示按钮**一颗三种身份**（`hintModeOf`）：没选牌是 `提示`（循环 bot.suggest 的候选）；
  选了几张但还凑不成一手是 `补齐`（只在**包含已选牌**的合法整手里找，已选的牌一张不动，
  默认给"不带分、牌小"的最保守那一手）；已经是合法的一手了是 `换一手`。
  一个候选都找不到时弹一句「这几张凑不成一手，先放下再提示」，**不动选中态**。
- 出牌按钮文案随选牌变化：`出牌 · 对子` / `出牌 · 拖拉机 ×2` / `甩牌 5 张`；不合法时按钮灰且下方一行说明原因（"首出是对子，你还有黑桃对子必须出"）。
- 亮主条只在窗口内出现：按钮按档位排 `♠5 亮主` `♠5 一对` `小王一对 无主` … 只显示手里做得到的；`不亮` 灰按钮。
- **抄底条**（`client/sj/ChaoBar.tsx`）：轮到我时列出所有**严格更强**的亮法按钮（文案 `♠5 一对 · 抄底`）
  加一颗 `不抄` 灰按钮、倒计时，和一行「抄底会拿走 8 张底牌重扣，并把主变成你亮的花色」；
  不轮到我时显示「正在问 X 是否抄底 · 还剩 Ns」和当前主花色/级别。
  按钮列表来自 `declareOptions(..., 'chao')`，与服务端的 `doChao` 同源 —— **点得亮的服务端一定收**。
- 扣底：33 张全部展开，点选 8 张，下方 8 个空槽逐个填入；`确认扣底` 只有恰好 8 张时可点；给一个 `帮我扣`（机器人策略）按钮。
  抄底者重新扣底时文案换成「你抄了底，重新扣 8 张」；别人视角显示的是 `kouSeat` 那个人，不是庄家。
- 看上一轮：按住显示上一圈四手牌与赢家。
- 轮到你：座位呼吸环（复用 TurnRing）+ 手牌整体轻微上浮 + 语音「该你啦」。
- 分牌：闲家赢到的分牌堆在记分板里可展开看具体牌。
- 断线/重连、房主移交、表情、改名、房规（turnSeconds、kouSeconds、autoContinue）与炸金花对齐。

### 3.5 动效编排（"蓄力 → 冲击 → 收束"，每一拍都有对应事件）

| 时刻 | 编排 |
| --- | --- |
| 发牌 `sj_deal` | 桌心牌堆逐张飞向四座，`SJ_DEAL_CARD_MS`（400ms）一张、轻微弧线与随机旋转（±6°），自己的牌落地即翻面；发完后手牌一次 FLIP 排序（600ms，spring）。音：每张一声极轻的 `deal`，音高逐张微升。 |
| 亮主 `sj_declare` | 亮的牌从手里**拍**到座位前（缩放 1.15→1，带阴影落地），花色符号从桌心炸开一圈粒子，桌面光池在 700ms 内变成该花色的颜色；反主时旧牌被"撞"飞（旋转滑出）。语音：「红桃主」「一对黑桃主」「无主！」。 |
| 抄底 `sj_chao` | 桌面压暗 → 亮出的牌从手里拍到台面（旧亮主者的明牌复用反主那一下的"撞飞"）→ 「抄底」戳记砸下 → 8 张底牌翻着背飞向抄底者 → 光池换成新主花色。 |
| 扣底 | 8 张底牌从桌心飞到 `kouSeat` 手里（别人看到的是 8 张牌背飞过去）；扣下的牌逐张翻到背面落进桌心"底"堆。抄底会再走一次这一拍。 |
| 出牌 `sj_play` | 牌从手牌滑到出牌区，多张之间 40ms 错开；**毙**（trumped）时冷钢蓝闪一下（复用比牌那个蓝）。 |
| 定圈 `sj_trick` | 赢家那手牌金边亮 300ms → 四手牌叠起飞向赢家座位；有分时**分牌先分离出来**，沿弧线飞到记分板分牌堆，得分环增长 + 数字滚动 + 叮（每张一声，音高上行）。 |
| 甩牌失败 `sj_throw_fail` | 甩出的牌抖一下弹回手中，只留最小单位；红色戳记「甩牌失败 −10」。 |
| 抠底 `sj_dig` | 桌面压暗，8 张底牌一字排开逐张翻面（120ms 一档），分牌高亮，倍数戳记 ×2/×4/×8 砸下（缩放 3→1 + 桌面抖动），总分滚动。语音「抠底！」。 |
| 结算 `sj_hand_end` | 得分环补满/定格 → 结果戳记（大光 / 小光 / 升 1 级 / 上台！）→ 级别徽章 3D 翻面到新级（5→10）伴金色爆闪 → 庄家标记飞向下一位庄。 |
| 通关 `sj_match_end` | 全屏金雨 + 桂冠落在赢队两个座位 + 「通关」大字，重复利用炸金花的 GoldRain/Laurel。 |
| 轮到我 | 呼吸环，手牌上浮 6px。 |

要求：入场用 `--spring` 过冲，同类元素时长/角度略有差异，弧线不走直线，`prefers-reduced-motion` 全部可关（沿用 styles.css 约定）。

### 3.6 声音与语音

**轮转只有提示音，没有语音。** 「轮到你了」这种每局要触发几十次的提醒，用人声念出来
很快就烦，是最先被玩家关掉的一句 —— 两个游戏都只留 `turn` 那一颗上行小铃。自己回合
只剩 5 秒时补一记 `hurry`（音量只有 `turn` 的三分之一）：倒计时环在头像上，低头在手牌
里挑牌时看不见。判断标准是**高频的状态提醒走音效，低频而有戏的时刻才配语音**。

**两个游戏的台词表是分开的，不许互相借用。** `client/voice-lines.ts` 里
`ZJH_VOICE_LINES` / `SJ_VOICE_LINES` 各一张，key 类型也拆成 `ZjhVoiceKey` / `SjVoiceKey`
两个联合，在升级的牌桌上播炸金花的台词是编译不过的（升级最早就是借了炸金花的「该你啦」
才串味的）。语音包连**发音人**也分开：炸金花是婷婷（女声），升级是 Reed（男声）。
台词表是纯数据、不碰 `window`，所以能被 node 测试直接钉住。

- 音效复用 `client/sound.ts` 的合成器，新增 `slam`（亮主/抄底拍牌）、`sweep`（收圈）、
  `stamp`（倍数戳记与抄底戳记）、`hurry`（快到点的轻滴答）。
- 升级台词：叫牌 `sj_trump_s/h/c/d`、`sj_trump_pair`（一对）、`sj_reinforce`、
  `sj_fanzhu`、`sj_nt`、`sj_chao`、`sj_kou`；出牌 `sj_pair`、`sj_tractor`、
  `sj_shuai`、`sj_shuai_fail`、`sj_diao`（吊主）、`sj_bi`（毙了）、`sj_gaibi`、`sj_dian`；
  收圈 `sj_fen`、`sj_last`；结算 `sj_dig`、`sj_dig2`（双抠）、`sj_levelup`、`sj_daguang`、
  `sj_xiaoguang`、`sj_shangtai`、`sj_shouzhu`、`sj_tongguan`。
- **连读而不是穷举组合**：`voice.play('sj_fanzhu', 'sj_trump_h')` 念成「反主！红桃主」，
  花色和事件各是一句短台词 —— 否则 4 个花色 × 4 种叫牌事件要录 16 句。
- **出牌只在有信息量的时刻出声**（`playVoice`）：一局 25 圈、100 手牌，每手都报牌型会吵到
  被关掉。首出报牌型与吊主，最后一圈额外报一句；跟牌只报毙 / 盖毙 / 垫出分牌，跟不上又
  没分的垫牌一律安静；收圈满 15 分才喊「有分！」。
- 用 `scripts/voice-pack.mjs` 重新生成语音包（macOS `say`），manifest 同步；台词删掉时
  对应的旧音频会被一并删除。

## 4. 命令行与 MCP —— 升级不做（用户已取消）

升级**只做网页版**。四人两队、25 张手牌的扇形选牌、亮主/扣底/甩牌这些交互在终端里
既排不下也点不动，硬做出来的是一个没人会用的东西。原计划的 `shared/sj/client.ts`、
CLI 的升级渲染、MCP 的 `sj_*` 动作**全部取消**。

仍然要保证的是**不崩**：`shared/client.ts` 收到 `kind !== 'zjh'` 的房间时，
一律报 `升级房间暂只支持网页版，请用浏览器打开这个房号` 并按 fatal 处理 ——
CLI 打印后退出（exit 1），MCP 把它作为工具错误返回。CLI/MCP 只会用不带 `kind`
的 `create` 建房，所以它们永远开不出一桌升级。炸金花的 CLI/MCP 行为完全不变。

## 5. 验收方案

### 5.1 自动化（合入前必须全绿）

- `sj-cards`：顺序表（有主/无主、级牌各种位置）、相邻关系（跳级牌、A→副级→主级→小王→大王）、分值。
- `sj-units`：对子/拖拉机识别（含跨级牌相邻、副级牌不相邻）、甩牌拆分。
- `sj-rules`：反主级别 7 档全序、单张之间不能互反、加固只抬到本花色档位、对王 6/7、不能自反（亮主可加固 / 抄底只剩对王）、亮法枚举；跟牌合法性 ≥ 30 个用例（有对必出对、拖拉机优先、不足张数、缺门垫/毙）；定圈 ≥ 20 个（毙、结构不匹配不算、相等先出赢、甩牌比法）；甩牌校验成功/失败与罚分；抠底倍数；升级表全部区间；庄家轮转；夹到顶级；通关条件。
- `sj-engine`：完整一局流程（发牌→亮主→反主→加固→扣底→**抄底**→打完 25 张→抠底→结算）；
  无人亮主 → 默认无主 → 跳过抄底直接开打，以及窗口 8s / 3s 两档；
  抄底的完整状态机（依次询问 → 有人抄 → 重新扣底 → 接着问 → 再有人抄 → 一轮无人抄才开打）；
  庄家不参与询问；不能自反、对王可以把自己反成无主；首局抄底换庄、第二局起不换庄；
  抄底之后仍是 4×25 + 底 8；扣底把自己的明牌扣下去时明牌 id 要摘掉；超时代打；断线代打；
  sanitize 不泄露（每个视角别人的 hand 为空；底牌在 `chao` 阶段谁都看不到、在 `kou` 阶段只给 `kouSeat`）；
  快照 migrate（含 strength 从 4 档换算成 7 档，且只换算一次）。
- `sj-client`：抄底条列出来的每一手服务端都收得下，没画出来的一手都收不下（客户端与服务端判定同源）。
- `sj-fuzz`：4 个机器人随机对局 **300 局** 不抛错、每局四家各出满 25 张且**圈数 ≤ 25**（见 1.4 的修正）、每一圈四家出牌张数相同、分数守恒（闲家分 + 庄家分 + 底牌分 = 200，罚分与抠底单独核）、每场比赛在 200 局内必然结束。随机种子可复现，失败时打印种子。
  抄底会让主花色在 `kou` 之后**还会变**，所以任何缓存了 `ctx` 的地方都必须在进 playing 之后才取。
- 炸金花原有 `tests/*.test.ts` 原样通过（不允许改断言）。
- `npm run typecheck`、`npm run build` 通过；`dist/server.mjs` 启动无警告。
