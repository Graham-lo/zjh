## 1. 规则规范（两副牌升级 / 拖拉机）

### 1.1 牌

- 两副标准扑克含大小王，共 108 张。每张牌有唯一 `id`（如 `S5a` / `S5b`、`JB a`），客户端按 id 选牌。
- 花色 `S H C D`，点数 2–14（J=11 Q=12 K=13 A=14）；小王 `{suit:'J', rank:15}`，大王 `{suit:'J', rank:16}`。
- **分牌**：5 = 5 分，10 = 10 分，K = 10 分。全场 200 分。

### 1.2 级牌、主牌、副牌

- 每队有自己的**级别**（level）。**庄家所在队的级别 = 本局级牌**。
- 有主花色 T 时，主牌从大到小：**大王 > 小王 > 主级牌（T 花色的级牌）> 副级牌（其他三色的级牌，三者相等）> T 花色 A > K > … > 2**（跳过级牌点数）。
- **无主**（NT）时主牌只有：**大王 > 小王 > 级牌（四色相等）**。
- 副牌：每门花色 A > K > … > 2，跳过级牌点数。
- 花色组（suit group）：`T`（主牌，含王和所有级牌）或 `S/H/C/D` 副牌。一张牌只属于一个组。

### 1.3 座位与队伍

- 座位 0–3 顺时针；**0 与 2 一队，1 与 3 一队**。大厅里可以点空座换座，方便朋友组队。
- 4 个座位必须坐满（真人或电脑）才能开局；房主可加电脑补位。
- 每队的级别在整场比赛中保留；房间新建时两队都在阶梯第一级（五十K 是 5，打通关是 2）。

### 1.4 一局的阶段

`lobby → dealing → declaring → kou → playing → hand_end → (下一局 dealing | match_end)`

**dealing（发牌）**
- 服务端一次性发好：从庄家（首局从房主）开始顺时针，每人 25 张，剩 8 张为底牌。
- 状态里带 `dealStartedAt`；客户端按 45ms/张 播发牌动画（共约 4.5s）。**亮主从发牌第一张起就开放**，
  服务端不限制"这张牌动画里发到没有"；客户端只在该牌已经飞到手里后才显示亮主按钮。
- 动画播完进入 declaring。

**declaring（亮主窗口）**
- 时长：发牌结束后 3s；每出现一次新的有效亮主/反主再延长 2s；四人都点了「不亮」立即结束。
- 亮主形式与强度（必须**严格更强**才能反主）：
  1. 单张级牌 → 定该花色为主（强度 1）
  2. 一对级牌（同花色两张）→ 定该花色为主（强度 2）
  3. 一对小王 → 无主（强度 3）
  4. 一对大王 → 无主（强度 4）
- **加固**：当前亮主者可用**同花色**的第二张级牌把强度 1 升到 2，别人再想反必须出王。
- 同一个人不能用**别的花色**反自己；可以用对王把自己的亮主反成无主。
- 亮出的牌**明牌放在该玩家座位前**直到扣底结束（仍在其手中，可正常打出）。
- 窗口结束时无人亮主：**翻底牌** —— 底牌第一张的花色为主，是王则无主；这张牌全场可见 1.2s 后归入底牌。
- **首局庄家 = 窗口结束时亮主有效的那个人**；无人亮主则房主坐庄。后续局庄家按 1.8 轮转，亮主只决定主花色。

**kou（扣底）**
- 庄家拿到 8 张底牌（只有庄家能看到），从 33 张里扣回 8 张（任意牌，含分牌和主牌都行）。
- 时限 45s；超时由机器人策略代扣。
- 扣完立即进入 playing，庄家首出。

**playing（出牌）**
- 每人每步时限 `turnSeconds`（默认 30s，房主可调 10–180）；超时由机器人策略代出一手**合法**牌。**没有弃牌概念。**
- **四家手牌出完即进入 hand_end。**每人 25 张，但一圈消耗的张数取决于首出的牌型（单张 1 张、对子 2 张、拖拉机更多），所以一局的**圈数是 1–25 之间的变量，不是固定 25 圈**；恒成立的是「每一圈四家出牌张数相同」「一局四家各出满 25 张」。
  （初稿写的"25 轮"是把 25 张牌误当成 25 圈，按中国升级竞赛规则修正。）

### 1.5 牌型（首出）

同一花色组内：
- **单张**
- **对子**：两张完全相同的牌（同花色同点数，来自两副）。
- **拖拉机**：≥2 个**点数相邻**的对子，同一花色组。相邻按 1.2 的顺序判定（跳过级牌点数，所以打 10 时 9 与 J 相邻）。
  主牌里 `T 花色 A → 副级牌 → 主级牌 → 小王 → 大王` 也相邻（对 A + 对副级 = 拖拉机；对主级 + 对小王 = 拖拉机）。
  三张不同花色的副级牌互相**相等**，不相邻，不能连成拖拉机。无主时 `级牌（同花色对）→ 小王 → 大王` 相邻。
- **甩牌**：同一花色组内多个单位（单张/对子/拖拉机）一起出。**合法条件**：每个单位都是其他三家手里该组同类单位中的**最大**
  （单张要压过别人所有该组单张；对子要压过别人所有该组对子；n 连对要压过别人所有该组 ≥n 连对；比较用最高牌）。
  服务端拿全部手牌判定。**甩牌失败**：只能出甩出的牌里**最小的那个单位**，其余退回手中，并**罚 10 分**：
  闲家失败 → 闲家 −10；庄家阵营失败 → 闲家 +10。客户端无法预判甩牌合法性，出牌后由服务端裁决并回一个 `sj_throw_fail` 事件。

### 1.6 跟牌

设首出在花色组 G，结构为 `(拖拉机长度列表 tr, 对子数 p, 单张数 s)`，总张数 n。跟牌者必须出 n 张，规则按优先级：

1. **有 G 必跟 G**：手里 G 的张数 ≥ n 时必须全出 G；不足时 G 全出、其余任意。
2. 出 G 时**结构尽量匹配**：
   a. 首出含拖拉机：按长度从长到短，每个拖拉机若手里有 G 的同长度（或更长拆出）拖拉机，必须出一个；
   b. 剩余的对子槽位（含未能配上的拖拉机拆成的对子槽位）若手里还有 G 的对子，必须用对子填；
   c. 剩余槽位用任意 G 单张填。
3. 没有 G：任意垫牌，或全出主牌**毙**。

合法性由 `shared/sj/rules.ts` 的 `validateFollow(hand, lead, play)` 判定，服务端与客户端共用一份；客户端只用自己的手牌即可完整判定跟牌合法性（甩牌合法性除外）。

### 1.7 定圈（谁赢这一轮）

- 一手牌能"参与比大小"当且仅当：**全部来自 G 且结构与首出完全一致**，或（G 不是主时）**全部是主牌且结构与首出完全一致**（对子毙对子、n 连对毙 n 连对、甩牌逐单位匹配）。其他跟法只是垫牌。
- 主牌毙 > G 内跟牌。同类之间比：单张比点数；对子比点数；拖拉机比最高对；甩牌比**最高优先单位**（最长拖拉机 > 对子 > 单张）的最高牌。
- 相等（三色副级牌、两副同牌）：**先出者赢**。
- 这一轮的分牌归赢家一队；只累计**闲家**得分 `defenderPoints`。

### 1.8 抠底与结算

- 最后一圈（手牌出完的那一圈）由闲家赢：**底牌分 × 2^n**，n = 闲家这轮获胜那手牌的张数（单张 ×2，对子 ×4，两连对 ×16，甩牌按总张数），上限 ×64。计入闲家得分。
- 闲家得分 s（含抠底与罚分）→ 结果：

| s | 结果 |
| --- | --- |
| s < 0 | 庄家升 4 级 |
| s = 0 | 庄家升 3 级（**大光**） |
| 5 ≤ s < 40 | 庄家升 2 级（**小光**） |
| 40 ≤ s < 80 | 庄家升 1 级 |
| 80 ≤ s < 120 | 闲家上台，不升级 |
| 120 ≤ s < 160 | 闲家上台，升 1 级 |
| 160 ≤ s < 200 | 闲家上台，升 2 级 |
| s ≥ 200 | 闲家上台，升 3 级 |

- **庄家轮转**：庄家守住（s < 80）→ **庄家的对家**坐庄；被打下（s ≥ 80）→ **庄家的下家**（顺时针下一位，必是闲家）坐庄。
- **升级夹到阶梯顶**：不能越过顶级（五十K 是 K，打通关是 A）。
- **通关**：**处于顶级的队作为庄家守住一局**即赢下整场比赛 → `match_end`。顶级的队被打下则留在顶级、丢庄。
- hand_end 展示 9s（抠底翻牌 + 计分 + 升级动画都要看完），然后自动发下一局（房主可提前点「下一局」）。
- match_end：展示通关庆祝；「再来一场」把两队级别重置到阶梯首级，庄家重新由亮主决定。

### 1.9 断线、超时、退出

- 断线保留座位；轮到掉线者由机器人策略代打（不等待）。回来即接管。
- 局中有人「离开」：座位由电脑接管到本场结束；大厅里离开则空出座位。
- 房主掉线 20s 移交（沿用炸金花逻辑）。

### 1.10 机器人（也是超时代打与「提示」的来源）

`shared/sj/bot.ts` 纯函数、确定性（可注入随机源）。要求"像个会打的朋友"，不要求强：

- **亮主**：有级牌且该花色（含级牌与王）≥ 7 张就亮单张；有对级牌且该色 ≥ 8 张亮对；对王且主牌总数 ≥ 9 时反无主。绝不为反而反：只在自己主更多时反。
- **扣底**：优先扣副牌里张数最少的花色的非分牌单张（造缺门），其次扣其他副牌小单张；不扣主牌、对子、分牌，除非没得扣。
- **首出**：有确定最大的单位（自己手里是该组当前最大）先出；否则出最长的副牌花色的小单张；主牌够多时（≥ 9 张）先用主牌小对子/单张"抽主"。
- **跟牌**：能赢且这轮有分或轮次靠后 → 用最小能赢的牌；对家已稳赢 → 垫分牌（给分）；否则出最小、不带分的牌。缺门时：这轮分 ≥ 10 且能毙 → 用最小能毙的主毙；否则垫分给对家或垫最小。
- **提示按钮**：客户端复用 `bot.suggest(handOnly)`，只用自己手牌与公开信息。

## 2. 架构：多游戏房间框架

### 2.1 原则

- `shared/` 依旧运行时无关；升级内核完全在 `shared/sj/`，不 import 炸金花内核。
- 房间用 `kind` 区分：`'zjh' | 'sj_510k' | 'sj_2a'`。炸金花的 `RoomState` 加 `kind: 'zjh'`（`migrateRoom` 给老快照补默认值），**其余不动**。
- Hub 变成对 `GameEngine` 接口的调度器，炸金花包一层适配器，行为零变化（现有测试必须原样通过）。

### 2.3 协议

```ts
// ClientMsg
| ({ t: 'create'; kind?: GameKind } & ClientHello)   // 缺省 'zjh'
// AnyPublicRoom = PublicRoom(zjh) | SjPublicRoom；两者都有 kind、code、viewerId、players、phase、log、chat
// GameEvent |= SjEvent
type SjEvent =
  | { k: 'sj_deal'; handNo: number; dealerSeat: number }
  | { k: 'sj_declare'; playerId: string; trump: Suit | 'NT'; strength: 1|2|3|4; cardIds: string[]; reinforce: boolean }
  | { k: 'sj_flip'; card: SjCard; trump: Suit | 'NT' }        // 翻底牌定主
  | { k: 'sj_kou_done'; playerId: string }
  | { k: 'sj_play'; playerId: string; cardIds: string[]; unit: 'single'|'pair'|'tractor'|'throw'; trumped: boolean }
  | { k: 'sj_throw_fail'; playerId: string; forcedIds: string[]; penalty: number }
  | { k: 'sj_trick'; winnerId: string; points: number; toDefenders: boolean; trickNo: number }
  | { k: 'sj_dig'; winnerId: string; base: number; multiplier: number; total: number }  // 抠底
  | { k: 'sj_hand_end'; defenderPoints: number; outcome: SjOutcome }
  | { k: 'sj_match_end'; winnerTeam: 0 | 1 }
  | { k: 'sj_turn'; playerId: string }
```

事件只驱动表演，状态永远以 room 为准（沿用炸金花的约定）。

### 2.4 SjRoomState（要点）

```ts
interface SjRoomState {
  kind: 'sj_510k' | 'sj_2a'; id; code; hostId; createdAt; log; chat; actionSeq;
  settings: { turnSeconds: number; kouSeconds: number; autoContinue: boolean };
  players: SjPlayer[];           // seat 0-3；team = seat % 2；hand: SjCard[]（服务端）
  phase: 'lobby'|'dealing'|'declaring'|'kou'|'playing'|'hand_end'|'match_end';
  levels: [number, number];      // 两队级别（阶梯里的点数）
  handNo; dealerSeat;            // 庄家座位
  trump: { suit: Suit|'NT'|null; level: number; declarerId: string|null; strength: number; cardIds: string[] };
  passed: string[];              // 本局点过「不亮」的人
  dealStartedAt; declareEndsAt; turnDeadline;
  bottom: SjCard[];              // 底牌（服务端；扣底后是庄家扣下的 8 张）
  bottomRevealed: boolean;       // 抠底/局末公开
  trickNo; leaderSeat; turnSeat;
  trick: { seat: number; cardIds: string[] }[];   // 当前圈已出
  lastTrick: {...} | null;       // 上一圈，给「看上一轮」
  defenderPoints: number;        // 闲家得分（含罚分）
  capturedPointCards: SjCard[];  // 闲家赢到的分牌（展示分牌堆）
  result?: { defenderPoints; dig?: {base; multiplier; total}; outcome; nextDealerSeat; levelsAfter }
  matchWinner?: 0|1;
}
```

`sanitize(state, viewerId)`：只给自己的 `hand`；别人只给 `handCount`；底牌只在 `kou` 阶段给庄家、`bottomRevealed` 后给所有人；亮主牌、当前圈、上一圈、分牌堆公开。**任何测试都要断言别人的手牌不会出现在响应里。**

### 2.5 Hub 定时器

| 阶段 | 定时 | 到点动作 |
| --- | --- | --- |
| dealing | dealStartedAt + 4.6s | → declaring，declareEndsAt = now + 3s |
| declaring | declareEndsAt（每次有效亮主 +2s） | 无人亮 → 翻底牌；→ kou |
| kou | kouSeconds | 机器人代扣 |
| playing | turnSeconds；机器人 500–1100ms 思考 | 机器人策略代出 |
| hand_end | 9s | 下一局（autoContinue）或等房主 |

服务端每次状态变更仍是 `broadcast(room, events)` + 防抖快照；账户统计在 hand_end/match_end 写回。

### 2.6 兼容

- 老快照没有 `kind` → `'zjh'`。

## 3. 客户端设计

### 3.1 首页（重设计）

结构从"一个游戏 + 入座卡"变成 **「选桌 → 入座」**：

- 左侧品牌区保留 `午夜牌会` 的气质（墨绿近黑 + 香槟金、大花色水印、发丝金线），标题改为 **「牌 会」**（eyebrow：私人牌会 · FRIENDS ONLY），lead 改成一句涵盖两种游戏的话。
- 中间是**三张"桌卡"**（Game cards），横排（≥1200px）/ 纵排（手机）：
  1. **炸金花** —— 2–6 人 · 豹子 顺金 金花 阶梯丝带 · 三张悬浮牌（沿用现有 hero）。
  2. **升级 · 五十K** —— 4 人 · 两副牌 · 阶梯 `5 → 10 → K` 三枚级牌徽章。
  3. **升级 · 打通关** —— 4 人 · 两副牌 · 阶梯 `2 … A` 十三格细丝带，当前高亮 2。
  每张桌卡：顶部游戏名（衬线金渐变）、一行规则 tagline、人数/副数小标、底部 **「开一桌」** 主按钮。
  选中态：卡片抬起 + 金边 + 桌面绒布色泛起（炸金花墨绿、升级用**深蓝墨**）。
- 右侧入座卡不变（头像、昵称、房号六格、加入）。**加入房间不需要选游戏**，房号决定一切；受邀链接直接进入。
- 桌卡 hover/选中的绒布色，就是进入后牌桌的底色 —— 从首页到牌桌的颜色连续。

### 3.2 升级牌桌：视觉语言

- 和炸金花同一套 token（金三层、玻璃面板、发丝线、字体栈），但绒布换成**深蓝墨**（`--sj-felt: #14294a / --sj-felt-2: #0c1a33`），
  一眼能分辨"这是另一间房"。**主花色定下后，桌面顶灯的光池色随主花色变**：♠ 冷石墨、♥ 绛红、♣ 森绿、♦ 琥珀、无主 紫罗兰。这是整桌最强的记忆点。
- 牌沿用 `PlayingCard`（正反面、3D 翻面），新增 `size="hand"`（手牌扇）和王牌面（大王金冠、小王银冠，Joker 竖排文字）。

### 3.3 布局

**桌面（≥1200px）**：三栏。左栏 **记分板**（两队级别徽章、庄家标记、主花色大徽章、闲家得分环 0→80→200、分牌堆缩略、底牌 8 张牌背、圈数与已出张数「第 n 圈 · 已出 m/25 张」）；中栏牌桌；右栏 记录/聊天（沿用 Dock 常驻）。
牌桌：对家在上、左右为对手、我在下。每个座位前有一个**出牌区**，当前圈四手牌各落在各自座位前。
我的手牌：**底部扇形**（25 张，自动排序：主牌在左 → 副牌按 ♠♥♣♦），可横向缩放，卡片间距随宽度自适应；选中抬起 14px。
操作条在手牌上方：`提示` `出牌`（只在选牌合法时点亮）`看上一轮`。
**手机（≤780px）**：记分板压缩成顶栏一行（级别 · 主 · 闲家分/80）+ 可展开；手牌两行扇形或横向滚动（≥ 25 张在 390px 上不能一行），选牌抬起；出牌按钮固定底部。

**大屏**：沿用 `--card-*`/`--seat-*` 变量放大策略；≥1880px 手牌卡 `--card-hand-w` 92px。

### 3.4 交互细节（必须做到）

- 选牌：点一张切换；**双击一张自动选中它的对子**（有的话）；长按/拖动横扫多选（手机）。
- `提示`：循环给出合法出法（复用 bot.suggest），每按一次换下一个候选，选中态用金色抬起。
- 出牌按钮文案随选牌变化：`出牌 · 对子` / `出牌 · 拖拉机 ×2` / `甩牌 5 张`；不合法时按钮灰且下方一行说明原因（"首出是对子，你还有黑桃对子必须出"）。
- 亮主条只在窗口内出现：按钮按强度排 `♠5 亮主` `♠5 一对` `小王一对 无主` … 只显示手里做得到的；`不亮` 灰按钮。
- 扣底：33 张全部展开，点选 8 张，下方 8 个空槽逐个填入；`确认扣底` 只有恰好 8 张时可点；给一个 `帮我扣`（机器人策略）按钮。
- 看上一轮：按住显示上一圈四手牌与赢家。
- 轮到你：座位呼吸环（复用 TurnRing）+ 手牌整体轻微上浮 + 语音「该你啦」。
- 分牌：闲家赢到的分牌堆在记分板里可展开看具体牌。
- 断线/重连、房主移交、聊天、表情、改名、房规（turnSeconds、kouSeconds、autoContinue）与炸金花对齐。

### 3.5 动效编排（"蓄力 → 冲击 → 收束"，每一拍都有对应事件）

| 时刻 | 编排 |
| --- | --- |
| 发牌 `sj_deal` | 桌心牌堆逐张飞向四座，45ms 一张、轻微弧线与随机旋转（±6°），自己的牌落地即翻面；发完后手牌一次 FLIP 排序（600ms，spring）。音：每张一声极轻的 `deal`，音高逐张微升。 |
| 亮主 `sj_declare` | 亮的牌从手里**拍**到座位前（缩放 1.15→1，带阴影落地），花色符号从桌心炸开一圈粒子，桌面光池在 700ms 内变成该花色的颜色；反主时旧牌被"撞"飞（旋转滑出）。语音：「红桃主」「一对黑桃主」「无主！」。 |
| 翻底定主 `sj_flip` | 底牌第一张翻起悬停 1.2s，同样触发光池变色。 |
| 扣底 | 8 张底牌从桌心飞到庄家手里（别人看到的是 8 张牌背飞过去）；扣下的牌逐张翻到背面落进桌心"底"堆。 |
| 出牌 `sj_play` | 牌从手牌滑到出牌区，多张之间 40ms 错开；**毙**（trumped）时冷钢蓝闪一下（复用比牌那个蓝）。 |
| 定圈 `sj_trick` | 赢家那手牌金边亮 300ms → 四手牌叠起飞向赢家座位；有分时**分牌先分离出来**，沿弧线飞到记分板分牌堆，得分环增长 + 数字滚动 + 叮（每张一声，音高上行）。 |
| 甩牌失败 `sj_throw_fail` | 甩出的牌抖一下弹回手中，只留最小单位；红色戳记「甩牌失败 −10」。 |
| 抠底 `sj_dig` | 桌面压暗，8 张底牌一字排开逐张翻面（120ms 一档），分牌高亮，倍数戳记 ×2/×4/×16 砸下（缩放 3→1 + 桌面抖动），总分滚动。语音「抠底！」。 |
| 结算 `sj_hand_end` | 得分环补满/定格 → 结果戳记（大光 / 小光 / 升 1 级 / 上台！）→ 级别徽章 3D 翻面到新级（5→10）伴金色爆闪 → 庄家标记飞向下一位庄。 |
| 通关 `sj_match_end` | 全屏金雨 + 桂冠落在赢队两个座位 + 「通关」大字，重复利用炸金花的 GoldRain/Laurel。 |
| 轮到我 | 呼吸环，手牌上浮 6px。 |

要求：入场用 `--spring` 过冲，同类元素时长/角度略有差异，弧线不走直线，`prefers-reduced-motion` 全部可关（沿用 styles.css 约定）。

### 3.6 声音与语音

- 音效复用 `client/sound.ts` 的合成器，新增 `slam`（亮主）、`sweep`（收圈）、`stamp`（倍数戳记）。
- 语音新增台词（`VOICE_LINES`）：`trump_s/h/c/d`（黑桃主…）、`trump_pair`（一对）、`nt`（无主）、`kou`（扣底）、`bi`（毙）、`dig`（抠底）、`levelup`、`daguang`、`xiaoguang`、`shangtai`（上台）、`tongguan`。
  用 `scripts/voice-pack.mjs` 重新生成语音包（macOS `say`），manifest 同步。

## 4. 命令行与 MCP —— 升级不做（用户已取消）

升级**只做网页版**。四人两队、25 张手牌的扇形选牌、亮主/扣底/甩牌这些交互在终端里
既排不下也点不动，硬做出来的是一个没人会用的东西。原计划的 `shared/sj/client.ts`、
CLI 的升级渲染、MCP 的 `sj_*` 动作**全部取消**。

仍然要保证的是**不崩**：`shared/client.ts` 收到 `kind !== 'zjh'` 的房间时，
一律报 `升级房间暂只支持网页版，请用浏览器打开这个房号` 并按 fatal 处理 ——
CLI 打印后退出（exit 1），MCP 把它作为工具错误返回。CLI/MCP 只会用不带 `kind`
的 `create` 建房，所以它们永远开不出一桌升级。炸金花的 CLI/MCP 行为完全不变。

## 5. 验收方案

### 5.1 自动化（合入前必须全绿）

- `sj-cards`：顺序表（有主/无主、级牌各种位置）、相邻关系（跳级牌、A→副级→主级→小王→大王）、分值。
- `sj-units`：对子/拖拉机识别（含跨级牌相邻、副级牌不相邻）、甩牌拆分。
- `sj-rules`：跟牌合法性 ≥ 30 个用例（有对必出对、拖拉机优先、不足张数、缺门垫/毙）；定圈 ≥ 20 个（毙、结构不匹配不算、相等先出赢、甩牌比法）；甩牌校验成功/失败与罚分；抠底倍数；升级表全部区间；庄家轮转；夹到顶级；通关条件。
- `sj-engine`：完整一局流程（发牌→亮主→反主→加固→扣底→打完 25 张→抠底→结算）；翻底定主；超时代打；断线代打；sanitize 不泄露（对每个视角断言别人的 hand 为空、底牌只在该看的时候可见）；快照 migrate。
- `sj-fuzz`：4 个机器人随机对局 **300 局** 不抛错、每局四家各出满 25 张且**圈数 ≤ 25**（见 1.4 的修正）、每一圈四家出牌张数相同、分数守恒（闲家分 + 庄家分 + 底牌分 = 200，罚分与抠底单独核）、每场比赛在 200 局内必然结束。随机种子可复现，失败时打印种子。
- 炸金花原有 `tests/*.test.ts` 原样通过（不允许改断言）。
- `npm run typecheck`、`npm run build` 通过；`dist/server.mjs` 启动无警告。

### 5.2 浏览器验收（主线程亲自做，桌面 1440×900 与手机 390×844 各一遍）

1. 首页三张桌卡可选，颜色随选桌变化；创建五十K 房间、加 3 个电脑、开局。
2. 发牌动画、亮主按钮随牌到手出现、亮主后桌面变色、反主撞飞、扣底 8 槽、首出、跟牌非法时的说明文字、提示按钮循环、定圈飞牌与分牌入堆、抠底翻牌与倍数戳记、结算翻级、下一局自动开始。
3. 刷新页面恢复座位与手牌；手机端手牌可滚可选可出。
4. 打通关房间从 2 开始；两个房间同时存在互不影响；炸金花房间照常。
5. 大屏（≥1880px）内容按比例放大，记分板与聊天常驻两侧。
