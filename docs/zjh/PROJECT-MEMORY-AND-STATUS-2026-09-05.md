- 产品是少数朋友玩的虚拟积分游戏；不做充值、提现、转让或兑换。优先交互延迟、牌桌质感、动画与细节。
- 自托管单 Node 进程、内存权威状态、WebSocket、SQLite 快照。记忆中的部署目标是 VPS 96 的 `zjh` 服务，不是 VPS 107；线上身份须现场验证。
- 机器人以具体人物卡建模，有习惯、情绪、可观察和可利用的破绽。所有选择由场景与人物当前状态决定，不能恢复“第 N 轮强制看牌”之类的机械决策规则。
- 人性底层 `shared/mind/` 必须保持领域无关；炸金花只是适配器。七情、驱力、双系统、行为规律与人物天性分层，不能把牌类依赖引入通用层。
- 调优依赖决策留痕和真人同场景数据。记录不得成为偷看通道，写入失败不得阻断牌局。
- 既定交付方式是阶段通过验收后分批上线，P2 与留痕先行、P3 后续；不再沿用“一次性全做完才上线”的旧计划。本次状态查询不执行部署。
- 房主级功能要同步 Web、CLI、MCP，并提供中文说明。该要求针对炸金花；升级明确不新增 CLI/MCP。
- 梭哈遵循已经确定的主流规则：发起者全押、不按最短筹码封顶，其他玩家按看牌倍率接或弃，短码由边池结算；不足跟注者不能用更便宜的梭哈替代。
- “轮到你了”统一提示音，两个游戏都不用人声；升级使用独立语音词汇。宽屏必须充分利用空间；常用操作直接按钮化；删功能后要收回空白布局。
- 升级的既定边界：两副牌、四人对家、独立房型；选牌/悬停不能改变单张牌位置，系统建议可逐张取消，支持拖选。这里只同步这些边界，没有重新审计升级全部任务。
